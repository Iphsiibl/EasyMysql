# 09 · 函数速查：日期、字符串与 NULL 的处理

> **一句话价值**：拿到一份「遇到就能查」的常用函数清单，并改掉 `WHERE YEAR(x)=2024` 这种一写就被打回的条件。

**难度**：⭐⭐　|　**时长**：约 25 分钟　|　**涉及表**：`users`、`orders`、`students`、`bad_design_demo`

## 什么时候你会遇到它

你写了个 `WHERE YEAR(created_at) = 2024`，review 的人皱着眉头让你改。老板说「按月统计销售额」，你查了一晚上发现表里根本没有「月」这个字段。

函数不是查手册才用得上的东西，它是 SQL 里最常用的零件；但**同一个函数，写在 `SELECT` 后面是帮手，写在 `WHERE` 的列上就是灾难**，本篇把这条讲透。

## 本篇你会学到

- [ ] 字符串：`CONCAT` / `LEFT` / `CHAR_LENGTH`，以及字符数和字节数的区别
- [ ] 日期：`DATE_FORMAT` 按月统计订单、`DATEDIFF`、`LAST_DAY`
- [ ] **重点**：为什么 `WHERE YEAR(created_at)=2024` 要改写成范围查询（用 `EXPLAIN` 的 `rows` 和 `key_len` 证明）
- [ ] NULL 三兄弟 `IFNULL` / `COALESCE` / `NULLIF` 各自的脾气
- [ ] `CASE WHEN` 做行转列，把「一列分数」拧成「几个分类列」

## 正文

### 1. 字符串：拼、切、量

```sql
SELECT CONCAT(name, '（', city, '）') AS 标签 FROM students LIMIT 5;
```

```text
+-----------------------+
| 标签                  |
+-----------------------+
| 赵伟（上海）          |
| 赵芳（广州）          |
| 赵娜（深圳）          |
| 赵秀英（杭州）        |
| 赵敏（成都）          |
+-----------------------+
```

`CONCAT` 把任意多个片段接成一个，中间想插什么都行。但它有个脾气：**只要有一个参数是 NULL，整个结果就是 NULL**，不会把 NULL 当成空串拼进去：

```sql
SELECT CONCAT('前缀', NULL) AS 直接拼的结果, CONCAT('前缀', COALESCE(NULL, '（空）')) AS 兜底后的结果;
```

```text
+--------------------+--------------------+
| 直接拼的结果       | 兜底后的结果       |
+--------------------+--------------------+
| NULL               | 前缀（空）         |
+--------------------+--------------------+
```

所以拼接用户填的字段时，先用 `COALESCE` 兜一层底更稳。下面一条同时演示切片和计数：

```sql
SELECT name, LEFT(name,1) AS 姓, RIGHT(name,1) AS 最后一个字,
       CHAR_LENGTH(name) AS 字符数, LENGTH(name) AS 字节数_utf8
FROM students LIMIT 5;
```

```text
+-----------+------+-----------------+-----------+----------------+
| name      | 姓   | 最后一个字      | 字符数    | 字节数_utf8    |
+-----------+------+-----------------+-----------+----------------+
| 冯丽      | 冯   | 丽              |         2 |              6 |
| 冯伟      | 冯   | 伟              |         2 |              6 |
| 冯军杰    | 冯   | 杰              |         3 |              9 |
| 冯刚      | 冯   | 刚              |         2 |              6 |
| 冯勇      | 冯   | 勇              |         2 |              6 |
+-----------+------+-----------------+-----------+----------------+
```

**`CHAR_LENGTH` 数的是「字符」，`LENGTH` 数的是「字节」**：库是 `utf8mb4`，一个汉字占 3 字节，所以「冯军杰」= 3 个字符、9 个字节。判断长度该用哪个？给人看的用 `CHAR_LENGTH`，算存储空间的用 `LENGTH`。`SUBSTRING`、`TRIM`、`REPLACE`、`LPAD/RPAD` 干的事和名字一样直白，文末的表里都能查到。

顺带说清字符集：`utf8mb4` 里的 `mb4` 指「一个字符最多占 4 字节」，所以 emoji 也装得下，而且照样只算 1 个字符：

```sql
SELECT CHAR_LENGTH('😀') AS 字符数, LENGTH('😀') AS 字节数;
```

```text
+-----------+-----------+
| 字符数    | 字节数    |
+-----------+-----------+
|         1 |         4 |
+-----------+-----------+
```

汉字 3 字节、ASCII 1 字节、emoji 4 字节，`LENGTH` 算的就是这笔账。页面上写「最多 20 个字」，校验得用 `CHAR_LENGTH`，才会和用户的直觉一致。

### 2. 日期：「月」是算出来的，不是存出来的

表里只有 `created_at` 这种精确到秒的时间戳，「月份」得自己**格式化**出来：

```sql
SELECT DATE_FORMAT(created_at, '%Y-%m') AS 月份,
       COUNT(*) AS 订单数, ROUND(SUM(amount),2) AS 销售额
FROM orders GROUP BY 月份 ORDER BY 月份 LIMIT 5;
```

```text
+---------+-----------+-------------+
| 月份    | 订单数    | 销售额      |
+---------+-----------+-------------+
| 2024-01 |     16987 | 51240990.80 |
| 2024-02 |     15892 | 47151155.15 |
| 2024-03 |     16988 | 51328895.39 |
| 2024-04 |     16440 | 49590909.94 |
| 2024-05 |     16988 | 51857191.37 |
+---------+-----------+-------------+
```

`%Y` 是四位年，`%m` 是两位月，格式串记不住就翻文末的表。注意 `GROUP BY 月份` 用的是**别名**，MySQL 允许这么写 —— 它拦的是你选了没分组的列，见文末「常见错误」。

格式串里补足两位也不是为了好看：**月、日不补零，字符串顺序就不等于时间顺序**。手写 `'2024-9'` 这种值，排序会直接乱掉：

```sql
SELECT x FROM (SELECT '2024-9' AS x UNION ALL SELECT '2024-10') t ORDER BY x;
```

```text
+---------+
| x       |
+---------+
| 2024-10 |
| 2024-9  |
+---------+
```

`DATE_FORMAT` 生成的 `%Y-%m` 永远是两位，字符串顺序恰好就是时间顺序，所以 `ORDER BY 月份` 敢直接写。

另外两个常用货：

```sql
SELECT name, birth_date, DATEDIFF(CURDATE(), birth_date) AS 出生天数 FROM students LIMIT 3;
SELECT LAST_DAY('2024-02-01') AS 二月最后一天;
```

```text
+--------+------------+--------------+
| name   | birth_date | 出生天数     |
+--------+------------+--------------+
| 赵伟   | 2005-09-02 |         7705 |
| 赵芳   | 2005-09-03 |         7704 |
| 赵娜   | 2005-09-04 |         7703 |
+--------+------------+--------------+
+--------------------+
| 二月最后一天       |
+--------------------+
| 2024-02-29         |
+--------------------+
```

`DATEDIFF(大, 小)` 返回天数差；`LAST_DAY` 直接给出当月最后一天 —— 2024 是闰年，所以是 29 号，这种细节让程序自己算容易错。两个函数只算到「天」这一级，要按小时统计得自己换算，报表里按天切分用它们就够了。

> 📌 顺带交代：上面的『出生天数』是**按我跑的那天**算的，你跑出来会比我大若干 —— 这个值每天 +1。
> 教程里其他输出都该和你一字不差，唯独依赖 `CURDATE()` / `NOW()` 的这几个会漂。
> 记住这个特性：**写报表逻辑时，凡是依赖「今天」的数字，测试时都要固定日期。**

### 3. 重点：`WHERE YEAR(created_at)=2024` 为什么被打回

先摸数据。本库 20 万单的下单时间：

```sql
SELECT MIN(created_at) AS 最早, MAX(created_at) AS 最晚, COUNT(*) AS 总数 FROM orders;
SELECT YEAR(created_at) AS 年, COUNT(*) AS 订单数 FROM orders GROUP BY YEAR(created_at) ORDER BY 年;
```

```text
+---------------------+---------------------+--------+
| 最早                | 最晚                | 总数   |
+---------------------+---------------------+--------+
| 2024-01-01 00:01:45 | 2024-12-30 23:57:24 | 200000 |
+---------------------+---------------------+--------+
+------+-----------+
| 年   | 订单数    |
+------+-----------+
| 2024 |    200000 |
+------+-----------+
```

**订单全在 2024 一年里**，按年过滤等于没过滤，看不出两种写法的差别。那就按月比 —— 反模式和正确写法各 `EXPLAIN` 一次：

```sql
EXPLAIN SELECT COUNT(*) FROM orders WHERE MONTH(created_at) = 6;
```

```text
+----+-------------+--------+------------+-------+---------------+---------------------------+---------+------+--------+----------+--------------------------+
| id | select_type | table  | partitions | type  | possible_keys | key                       | key_len | ref  | rows   | filtered | Extra                    |
+----+-------------+--------+------------+-------+---------------+---------------------------+---------+------+--------+----------+--------------------------+
|  1 | SIMPLE      | orders | NULL       | index | NULL          | idx_orders_status_created | 6       | NULL | 199430 |   100.00 | Using where; Using index |
+----+-------------+--------+------------+-------+---------------+---------------------------+---------+------+--------+----------+--------------------------+
```

```sql
EXPLAIN SELECT COUNT(*) FROM orders
WHERE created_at >= '2024-06-01' AND created_at < '2024-07-01';
```

```text
+----+-------------+--------+------------+-------+---------------------------+---------------------------+---------+------+-------+----------+----------------------------------------+
| id | select_type | table  | partitions | type  | possible_keys             | key                       | key_len | ref  | rows  | filtered | Extra                                  |
+----+-------------+--------+------------+-------+---------------------------+---------------------------+---------+------+-------+----------+----------------------------------------+
|  1 | SIMPLE      | orders | NULL       | range | idx_orders_status_created | idx_orders_status_created | 6       | NULL | 22154 |   100.00 | Using where; Using index for skip scan |
+----+-------------+--------+------------+-------+---------------------------+---------------------------+---------+------+-------+----------+----------------------------------------+
```

只看三列：

| | `MONTH(created_at)=6` | `created_at >= ... AND < ...` | 白话 |
|---|---|---|---|
| `type` | `index` | `range` | index = 整个索引挨个看，range = 从某一段开始截着看 |
| **`rows`** | **199430** | **22154** | **估算要读多少行** |
| `Extra` | Using where; Using index | Using where; **for skip scan** | 后者因为没给索引第一列 `status`，得分段跳着扫，仍然比全扫强得多 |

**为什么套个函数就不行**：索引里存的是排好序的 `created_at` 原值，你让数据库先算 `MONTH(每一行)` 再比 —— 它只能把 199430 行全取出来算一遍，排序优势作废。

再看联合索引 `idx_orders_status_created`（`status, created_at` 两列）的对照，`key_len` 直接暴露第 2 列有没有被用上：

```sql
EXPLAIN SELECT COUNT(*) FROM orders WHERE status = 'paid' AND YEAR(created_at) = 2024;
```

```text
+----+-------------+--------+------------+------+---------------------------+---------------------------+---------+-------+-------+----------+--------------------------+
| id | select_type | table  | partitions | type | possible_keys             | key                       | key_len | ref   | rows  | filtered | Extra                    |
+----+-------------+--------+------------+------+---------------------------+---------------------------+---------+-------+-------+----------+--------------------------+
|  1 | SIMPLE      | orders | NULL       | ref  | idx_orders_status_created | idx_orders_status_created | 1       | const | 95652 |   100.00 | Using where; Using index |
+----+-------------+--------+------------+------+---------------------------+---------------------------+---------+-------+-------+----------+--------------------------+
```

```sql
EXPLAIN SELECT COUNT(*) FROM orders
WHERE status = 'paid' AND created_at >= '2024-06-01' AND created_at < '2024-07-01';
```

```text
+----+-------------+--------+------------+-------+---------------------------+---------------------------+---------+-------+------+------+----------+--------------------------+
| id | select_type | table  | partitions | type  | possible_keys             | key                       | key_len | ref   | rows | filtered | Extra                    |
+----+-------------+--------+------------+-------+---------------------------+---------------------------+---------+-------+------+------+----------+--------------------------+
|  1 | SIMPLE      | orders | NULL       | range | idx_orders_status_created | idx_orders_status_created | 6       | NULL  | 4122 |   100.00 | Using where; Using index |
+----+-------------+--------+------------+-------+---------------------------+---------------------------+---------+-------+------+------+----------+--------------------------+
```

`status` 是 1 字节的 `enum`，`datetime` 是 5 字节，所以 **`key_len=1` 表示只用了索引第一列，`key_len=6` 表示两列全用上了**。`YEAR()` 把 `created_at` 那一段彻底废掉，5 万条 paid 订单只能挨个算 `YEAR()`；改成范围后 `rows` 从 95652 掉到 4122。

顺手数一下六月到底多少单，好知道 4122 是不是靠谱：

```sql
SELECT COUNT(*) AS 六月订单数 FROM orders
WHERE created_at >= '2024-06-01' AND created_at < '2024-07-01';
```

```text
+-----------------+
| 六月订单数      |
+-----------------+
|           16440 |
+-----------------+
```

（`EXPLAIN` 的 `rows` 是**估算**，别拿它当精确结果 —— 第 13 篇讲过，看它是为了判断扫描量级。）

这套改写在分页、报表、任何「按时间段查」的场景里都成立。判断有没有白扫，`EXPLAIN` 要三个地方一起看：`type` 从 `index` 变 `range` 是质变，`rows` 从十几万掉到几千是量变，`key_len` 变长说明联合索引后面的列也吃上了。

**规矩一句话：`WHERE` 里让列单独待着，跟常量比大小；想按范围查，就写 `列 >= 起点 AND 列 < 终点`。** 函数爱去哪儿去哪儿，`SELECT` 后面随便用。

### 4. NULL 三兄弟：`IFNULL` / `COALESCE` / `NULLIF`

先说实话：本数据集 20 行的 `remark` 一条 NULL 都没有，所以兜底演示得用字面量：

```sql
SELECT SUM(remark IS NULL) AS 备注为空的行数, COUNT(*) AS 总行数 FROM bad_design_demo;
```

```text
+-----------------------+-----------+
| 备注为空的行数        | 总行数    |
+-----------------------+-----------+
|                     0 |        20 |
+-----------------------+-----------+
```

```sql
SELECT IFNULL(NULL, '（空）')              AS 用_IFNULL,
       COALESCE(NULL, '中间值', '（兜底）') AS 用_COALESCE,
       NULLIF('教学用反面教材', '教学用反面教材') AS 用_NULLIF;
```

```text
+------------+--------------+------------+
| 用_IFNULL  | 用_COALESCE  | 用_NULLIF  |
+------------+--------------+------------+
| （空）     | 中间值       | NULL       |
+------------+--------------+------------+
```

| 函数 | 干什么 | 什么时候用 |
|---|---|---|
| `IFNULL(a, b)` | `a` 是 NULL 就给 `b` | 只有一个兜底值，图快 |
| `COALESCE(a, b, c, ...)` | 返回第一个不是 NULL 的 | **默认选它**，可以兜很多层 |
| `NULLIF(a, b)` | `a = b` 就返回 NULL | 反着用：让「相等」变成「没有」 |

`NULLIF` 配真实列看一眼（第 10 篇的反面教材表）：

```sql
SELECT id, remark, NULLIF(remark, '教学用反面教材') AS 用_NULLIF
FROM bad_design_demo LIMIT 3;
```

```text
+----+-----------------------+------------+
| id | remark                | 用_NULLIF  |
+----+-----------------------+------------+
|  1 | 教学用反面教材        | NULL       |
|  2 | 教学用反面教材        | NULL       |
|  3 | 教学用反面教材        | NULL       |
+----+-----------------------+------------+
```

NULL 的三条硬规矩，一条一条都有实跑撑着：

**规矩一：NULL 不是 0，也不是空串，是「不知道」。** 所以 `= NULL` 永远查不到东西，哪怕这列明明有值：

```sql
SELECT COUNT(*) AS 用等号查NULL的结果 FROM students WHERE id = NULL;
SELECT COUNT(*) AS 用IS_NOT_NULL的结果 FROM students WHERE id IS NOT NULL;
```

```text
+---------------------------+
| 用等号查NULL的结果        |
+---------------------------+
|                         0 |
+---------------------------+
+-------------------------+
| 用IS_NOT_NULL的结果     |
+-------------------------+
|                     200 |
+-------------------------+
```

判断 NULL 只能用 `IS NULL` / `IS NOT NULL`。

**规矩二：聚合函数跳过 NULL，不报错。**

```sql
SELECT AVG(x) AS 平均分 FROM (SELECT 80 AS x UNION ALL SELECT 90 UNION ALL SELECT NULL) t;
```

```text
+-----------+
| 平均分    |
+-----------+
|   85.0000 |
+-----------+
```

80 和 90 的平均是 85 —— NULL 既没参与也没捣乱。同一个道理在数数上更直观：

```sql
SELECT COUNT(*) AS 行数, COUNT(x) AS COUNT列 FROM (SELECT 80 AS x UNION ALL SELECT 90 UNION ALL SELECT NULL) t;
```

```text
+--------+----------+
| 行数   | COUNT列  |
+--------+----------+
|      3 |        2 |
+--------+----------+
```

**`COUNT(*)` 数的是行，`COUNT(列)` 数的是「这一列里有值的行」** —— 两者不相等时，中间就藏着 NULL。

配套还有一条：聚合把 NULL 跳过之后，要是**一行都没剩下**，结果不是 0，而是 NULL：

```sql
SELECT SUM(CASE WHEN score > 100 THEN 1 END) AS 全不满足的结果 FROM scores;
```

```text
+-----------------------+
| 全不满足的结果        |
+-----------------------+
|                  NULL |
+-----------------------+
```

`scores` 里最高 100 分，`score > 100` 一行都命不中，`SUM` 一个数都没收到，只能交 NULL。所以报表里「本月一笔成交都没有」和「金额恰好是 0」是两种长相，前端拿到 NULL 得自己兜底 —— 这正是 `COALESCE` 的用武之地。

### 5. `CASE WHEN`：把行拧成列

需求：一张表里同时看到每个学生「优秀、良好、及格、不及格」各几门。分数是一行一行的，分类却要一列一列摆 —— 这就是**行转列**的雏形：

```sql
SELECT s.name,
       SUM(CASE WHEN sc.score >= 90 THEN 1 ELSE 0 END) AS 优秀,
       SUM(CASE WHEN sc.score >= 80 THEN 1 ELSE 0 END) AS 良好,
       SUM(CASE WHEN sc.score >= 60 THEN 1 ELSE 0 END) AS 及格,
       SUM(CASE WHEN sc.score <  60 THEN 1 ELSE 0 END) AS 不及格
FROM students s
JOIN scores sc ON sc.student_id = s.id
GROUP BY s.id, s.name
ORDER BY 优秀 DESC, 不及格 DESC LIMIT 5;
```

```text
+-----------+--------+--------+--------+-----------+
| name      | 优秀   | 良好   | 及格   | 不及格    |
+-----------+--------+--------+--------+-----------+
| 郑秀英    |      7 |      7 |      7 |         3 |
| 李涛      |      5 |      5 |      6 |         4 |
| 李强磊    |      5 |      5 |      6 |         4 |
| 赵敏      |      5 |      6 |      7 |         3 |
| 孙桂      |      4 |      5 |      6 |         4 |
+-----------+--------+--------+--------+-----------+
```

读法：`CASE WHEN 分数 >= 90 THEN 1 ELSE 0 END` 把每行变成 0 或 1，外层 `SUM` 把这个学生的 1 全加起来 —— **满足条件的行数**就是这么来的。

同一个套路还有个更短的写法，MySQL 里布尔表达式的真值就是 1/0：

```sql
SELECT SUM(status = 'created')  AS 待付款, SUM(status = 'paid')     AS 已付款,
       SUM(status = 'shipped')  AS 已发货, SUM(status = 'cancelled') AS 已取消
FROM orders;
```

```text
+-----------+-----------+-----------+-----------+
| 待付款    | 已付款    | 已发货    | 已取消    |
+-----------+-----------+-----------+-----------+
|     50000 |     50000 |     50000 |     50000 |
+-----------+-----------+-----------+-----------+
```

一条 SQL 数出四种状态的订单数，不用 `GROUP BY`。`CASE WHEN` 还可以写多个 `WHEN` 分支、可以省略 `ELSE`（匹配不上就是 NULL）、可以配合 `AVG` 算及格率，但骨架就是上面这个。省略 `ELSE` 的代价是没命中的组拿到 NULL 而不是 0，做计数时写全 `ELSE 0` 更省心。

### 6. 常用函数速查表

| 分类 | 函数 | 干什么 |
|---|---|---|
| 字符串 | `CONCAT(a, b, ...)` | 拼成一个 |
| | `LEFT(s, n)` / `RIGHT(s, n)` | 取左/右 n 个字符 |
| | `SUBSTRING(s, 起, 长)` | 截取（`SUBSTR` 同义） |
| | `CHAR_LENGTH(s)` / `LENGTH(s)` | 字符数 / 字节数 |
| | `TRIM(s)` | 去首尾空格 |
| | `REPLACE(s, a, b)` | 把 a 换成 b |
| | `LPAD(s, n, c)` / `RPAD` | 左/右补足到 n 位 |
| 日期 | `NOW()` / `CURDATE()` | 当前时刻 / 当前日期 |
| | `DATE_FORMAT(d, 格式)` | 按格式转字符串（`%Y-%m-%d %H:%i:%s`） |
| | `YEAR(d)` / `MONTH(d)` / `DAY(d)` | 取年/月/日（**只在 `SELECT` 里用**） |
| | `DATEDIFF(a, b)` | 天数差（a − b） |
| | `DATE_ADD(d, INTERVAL n DAY)` | 加减时间 |
| | `LAST_DAY(d)` | 当月最后一天 |
| 数值 | `ROUND(x, n)` / `CEIL` / `FLOOR` | 四舍五入 / 向上 / 向下取整 |
| | `ABS(x)` | 绝对值 |
| 条件 | `IF(cond, a, b)` | 三元表达式 |
| | `IFNULL(a, b)` / `COALESCE(...)` | NULL 兜底（优先 COALESCE） |
| | `NULLIF(a, b)` | 相等就变 NULL |
| | `CASE WHEN ... THEN ... END` | 多分支，行转列的骨架 |
| 聚合 | `COUNT(*)` / `COUNT(列)` | 数行（`COUNT(列)` 跳过 NULL） |
| | `SUM` / `AVG` / `MAX` / `MIN` | 求和/平均/最值（**都跳过 NULL**） |

## 三个必须记住的结论

1. **函数套在列上，范围就没了**：`WHERE` 里永远写「列和常量比」，`MONTH()`/`YEAR()`/`CONCAT()` 只准出现在 `SELECT` 后面；判断有没有白扫，看 `EXPLAIN` 的 `type`、`rows` 和 `key_len`
2. **NULL 是「不知道」**：比较用 `IS NULL`，兜底用 `COALESCE`，聚合会跳过它 —— 所以 `COUNT(*)` 和 `COUNT(列)` 可能不一样
3. **分类统计用 `CASE WHEN` + `SUM`，按月统计用 `DATE_FORMAT` + `GROUP BY`**，这两个组合能覆盖你八成的报表需求

## 常见错误

### ❌ `SELECT` 里选了没分组的列

```sql
-- 会报 ERROR 1055，完整原文见下
SELECT status, DATE_FORMAT(created_at,'%Y-%m') AS 月份, COUNT(*)
FROM orders GROUP BY 月份 LIMIT 3;
```

真实报错原文：

```text
ERROR 1055 (42000) at line 1: Expression #1 of SELECT list is not in GROUP BY clause and contains nonaggregated column 'easy_mysql.orders.status' which is not functionally dependent on columns in GROUP BY clause; this is incompatible with sql_mode=only_full_group_by
```

**为什么错**：你按月份分组，却把 `status` 也选了出来。同一个月份里有 created/paid/shipped/cancelled 四种状态，数据库不知道该显示哪一行 —— MySQL 8 默认开着 `ONLY_FULL_GROUP_BY`，干脆不让你查。

**正确做法**：要么把 `status` 也放进 `GROUP BY`，要么把它变成聚合（比如数数）：

```sql
SELECT DATE_FORMAT(created_at,'%Y-%m') AS 月份, COUNT(*) AS 订单数, ROUND(SUM(amount),2) AS 销售额
FROM orders GROUP BY 月份 ORDER BY 月份 LIMIT 3;
```

```text
+---------+-----------+-------------+
| 月份    | 订单数    | 销售额      |
+---------+-----------+-------------+
| 2024-01 |     16987 | 51240990.80 |
| 2024-02 |     15892 | 47151155.15 |
| 2024-03 |     16988 | 51328895.39 |
+---------+-----------+-------------+
```
