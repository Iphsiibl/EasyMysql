# 22 · 权限与安全：别用 root 写代码

> **一句话价值**：学会给应用建只读账号、只写账号，并知道 SQL 注入该怎么防。

**难度**：⭐⭐　|　**时长**：约 30 分钟　|　**涉及表**：`users`、`orders`

## 什么时候你会遇到它

你的项目配置里写着 `user: root / password: easy123`。这条配置某天会出现在 GitHub 上。

## 本篇你会学到

- [ ] 用户、权限、角色的基本概念
- [ ] 最小权限原则：为什么应用账号不该有 `DROP`
- [ ] `CREATE USER` / `GRANT` / `REVOKE` 实操
- [ ] 读写分离账号怎么设计
- [ ] SQL 注入的原理与三种防御手段
- [ ] 连接配置该放在哪

## 正文大纲

1. **最小权限原则**：用一张表列出「运维 / 报表 / 应用」各需要什么权限
2. **建一个只读账号**：
   ```sql
   CREATE USER 'report'@'%' IDENTIFIED BY 'strong_password';
   GRANT SELECT ON easy_mysql.* TO 'report'@'%';
   ```
3. **验证权限确实生效**（用一个客户端连上去故意删一行）
4. **`%` host 的风险**与 `'report'@'192.168.1.%'` 的写法
5. **SQL 注入演示 + 三种防御**：预编译参数化（唯一正解）、白名单、存储过程
6. **连接配置放哪**：环境变量、配置中心、`.env` + `.gitignore`
7. **改密码、收回权限、删用户**

- [ ] 检查你现有项目的配置文件，找出所有硬编码的密码
