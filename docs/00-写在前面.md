# 00 · 写在前面：怎么用这个教程

> **一句话价值**：知道该怎么读这套教程，能少走 80% 的弯路。

**难度**：⭐　|　**时长**：约 8 分钟　|　**不涉及表**

## 什么时候你会遇到它

你点进这个仓库，看了一眼 23 篇文章的目录，关掉网页去刷抖音了。三天后你又想起来，还是没读。

问题不在你 —— 是**没人告诉你该怎么读**。

## 三条使用规则

### 规则一：一定要动手敲，不要只看

看 SQL 的文字描述，30 秒就懂了。理解它的意思，需要你亲手敲一遍、看到结果、故意改错一次。

**判断你有没有真的学会，只有一个标准**：关掉文章，你还能不能把那句 SQL 写出来。

### 规则二：跟着实验文件跑，不要复制粘贴

每篇都有一个配套文件，比如第 13 篇对应 `lab/queries/13-demo-index.sql`。

```powershell
cd lab
docker cp queries/13-demo-index.sql easy-mysql:/tmp/
docker exec easy-mysql mysql -uroot -peasy123 -t -e "source /tmp/13-demo-index.sql"
```

**关键**：文章里的输出和你的输出**应该一致**（数据是脚本生成的，固定不变）。
如果不一样，说明你环境有问题，回来找我，我帮你查。

### 规则三：慢的可以跳，索引那四篇别跳

- [02](02-db-table-row-column.md)、[05](05-order-limit-aggregate.md)、[09](09-functions.md) 看着累，可以先跳过
- [13](13-index-what.md) ~ [17](17-composite-index.md) 是**全仓库最有价值的五篇**，也是面试最常问的
  建议在这五篇上花的时间比其他所有加起来还多

| 要求 | 说明 |

## 时间怎么安排

**别一次学完。** 推荐这样：

```
第 1 周   第 01~03 篇        先能跑起来，能查数据
第 2 周   第 04~09 篇        能写统计查询（这周会有明显的成就感）
第 3 周   第 10~12 篇        建表不踩坑
第 4 周   第 13~17 篇        ★ 性能专题，这周最爽
第 5 周   第 18~20 篇        事务并发，概念最绕，慢一点
第 6 周   第 21~23 篇 + 附录 收尾，整理成自己的笔记
```

**每天 30 分钟，一周 4 篇**，比周末突击 8 小时有效得多 —— 因为 MySQL 忘得很快。

## 三个最容易踩的坑

### 坑 1：把教程当小说读

⚠️ 90% 的人卡在这里。

**症状**：读到第三篇觉得「这个我会啊」，然后就没有然后了。
**解法**：每读一段，合上文章凭记忆敲一遍。敲不出来就回去重读。

### 坑 2：Windows 用户的管道乱码

**症状**：把实验文件用管道传进容器，中文全报错。

```powershell
# ❌ 错误：PowerShell 会把 UTF-8 转成 GBK
Get-Content queries/13-demo-index.sql | docker exec -i easy-mysql mysql -uroot -peasy123
```

**解法**：用 `docker cp` 送文件进去（每个实验文件首行都有 `SET NAMES utf8mb4;` 兜底），
或者干脆在 Adminer 界面里跑。环境搭建细节见 [lab/README.md](../lab/README.md)。

### 坑 3：不敢改数据

**症状**：怕把 `orders` 表改坏了，于是只敢 `SELECT`，`UPDATE` 一行都不敢跑。

**解法**：

```powershell
cd lab
powershell -ExecutionPolicy Bypass -File reset.ps1
```

**30 秒回到出厂设置**，还会自动校验 8 张表的行数对不对。
有了这个，你就可以放心大胆地改数据、改索引、加约束 —— 这才是学得快的原因。

## 关于数据表

教程里有 8 张表，分两个场景：

```
学校场景：students（学生）  courses（课程）  scores（成绩）
          → 练查询，第 03~09 篇

电商场景：users（用户）    orders（订单）    orders_slow（订单·无索引）  order_items（明细）
          → 练性能，第 13~20 篇

反面教材：bad_design_demo
          → 故意写错的表，第 10 篇逐个拆
```

其中 `orders` 和 `orders_slow` 是一对**双胞胎**：字段完全一样、20 万行数据完全一样，
唯一区别是一个有索引一个没有。

所有关于「加索引快多少」的结论，都靠这一对表做出来的干净对比。
这也是本仓库和别的教程最大的区别 —— **不用你相信作者，跑一遍就知道。**
