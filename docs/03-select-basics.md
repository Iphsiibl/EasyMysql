# 03 · SELECT 入门：查出你想要的那几行

> **一句话价值**：用 SELECT 把表里的数据「取」出来，并且只取你要的列。

**难度**：⭐　|　**时长**：约 20 分钟　|　**涉及表**：`students`

## 什么时候你会遇到它

你敲了 `SELECT * FROM students;`，屏幕哗地滚出 200 行 7 列，眼睛都花了。你其实只想知道「北京的学生叫什么名字」——**问题不在于数据库答不出来，在于你没说清楚自己要什么。**

## 本篇你会学到

- [ ] SQL 的固定语序：`SELECT ... FROM ... [WHERE] [ORDER BY] [LIMIT]`
- [ ] `*` 的代价，以及「能不用就不用」的原因
- [ ] `AS` 给列起别名，把英文表头换成中文
- [ ] `LIMIT` 只看前几行
- [ ] `ORDER BY` 让结果排好队，`DESC` 反着排
- [ ] `DISTINCT` 把重复值挤掉

## 正文

### 1. 先背下这一句骨架

所有查询都是同一个句式，五段，顺序是**焊死的**：

```text
SELECT 要哪些列 FROM 哪张表 [WHERE 条件] [ORDER BY 排序列 [DESC]] [LIMIT 条数];
```

（上面这行不是能执行的 SQL，方括号表示可选、中文是占位符。）把它填满就是一条真语句：

```sql
SELECT name, city FROM students WHERE city = '北京' ORDER BY birth_date DESC LIMIT 5;
```

```text
+-----------+--------+
| name      | city   |
+-----------+--------+
| 陈刚      | 北京   |
| 陈军杰    | 北京   |
| 陈静      | 北京   |
| 冯英      | 北京   |
| 冯涛      | 北京   |
+-----------+--------+
```

对照着读一遍：`SELECT name, city` 决定了表头只有两列（所以你没看到 `id`、`birth_date`），`FROM students` 决定去哪张表拿，`WHERE city = '北京'` 只留北京的，`ORDER BY birth_date DESC` 按出生日期从大到小排，`LIMIT 5` 只交出 5 行。

`WHERE` 是下一篇的主角，今天先记住 `SELECT`、`FROM`、`ORDER BY`、`LIMIT` 这四段怎么咬合。**五段的顺序不能换**：`ORDER BY` 写在 `LIMIT` 后面会直接报语法错，原文在文末「常见错误」。

### 2. `SELECT *` 的代价：你真的每一列都要吗

配套实验的【1】是这条：

```sql
SELECT * FROM students;
```

`*` 是「所有列」。这张表 200 行、7 列，一次吐出 1400 个格子，`created_at` 全是同一个时间戳，对你这个问题毫无用处，却一样不落地滚出来。**在命令行里它刷屏，在网页接口里它占带宽，在第 13 篇里你会知道它还要多绕一圈回表。**

先看 10 行是什么样（配套实验的【2】，顺手借了个 `LIMIT`，第 4 节讲）：

```sql
SELECT * FROM students LIMIT 10;
```

```text
+----+-----------+--------+--------------+------------+--------+---------------------+
| id | name      | gender | class_name   | birth_date | city   | created_at          |

|  2 | 赵芳      | 男     | 软工210班    | 2005-09-03 | 广州   | 2026-10-07 09:29:59 |
|  3 | 赵娜      | 女     | 软工210班    | 2005-09-04 | 深圳   | 2026-10-07 09:29:59 |
|  4 | 赵秀英    | 男     | 软工210班    | 2005-09-05 | 杭州   | 2026-10-07 09:29:59 |
|  5 | 赵敏      | 女     | 软工210班    | 2005-09-06 | 成都   | 2026-10-07 09:29:59 |
|  6 | 赵静      | 男     | 软工210班    | 2005-09-07 | 北京   | 2026-10-07 09:29:59 |
|  7 | 赵丽      | 女     | 软工210班    | 2005-09-08 | 上海   | 2026-10-07 09:29:59 |
|  8 | 赵强磊    | 男     | 软工210班    | 2005-09-09 | 广州   | 2026-10-07 09:29:59 |

```

> 📌 和第 02 篇同一个提醒：`created_at` 是**初始化数据那一刻**的时间，你那边显示的会是
> 你自己 reset 的时刻，**这列不同很正常**；`id` 到 `city` 六列应该和我一字不差。

再看只要两列（配套实验的【3】）：

```sql
SELECT name, city FROM students LIMIT 10;
```

```text
+-----------+--------+
| name      | city   |
+-----------+--------+
| 赵伟      | 上海   |
| 赵芳      | 广州   |
| 赵娜      | 深圳   |
| 赵秀英    | 杭州   |
| 赵敏      | 成都   |
| 赵静      | 北京   |
| 赵丽      | 上海   |
| 赵强磊    | 广州   |
| 赵洋      | 深圳   |
| 赵艳      | 杭州   |
+-----------+--------+
```

**两段输出，一眼看出差距**：7 列变 2 列，行还是那 10 行，你要的信息一个不少。规矩很简单：**要几列写几列**，`*` 只配用在「我就是想看看这张表长什么样」的时候。

只写列名还有个附带好处：**列名敲错了当场就有回音**：

```sql
SELECT namee, city FROM students LIMIT 5;
```

```text
ERROR 1054 (42S22) at line 1: Unknown column 'namee' in 'field list'
```

报错把你打错的那列原样点名（`namee` 多打了一个 `e`）。`SELECT` 后面的列名必须和 `DESC students` 里的 `Field` 一字不差，没有模糊匹配。而 `SELECT *` 连这个机会都不给你 —— 它什么都收，也就什么都发现不了；等你的程序按「第几列」去取数据，表里悄悄多一列，取到的东西就全串位了。

### 3. `AS`：把表头换成你认识的字

数据库里的列名是英文或者拼音，给你自己看的报表得说人话：

```sql
SELECT name AS 姓名, city AS 城市, birth_date AS 出生日期
FROM students LIMIT 5;
```

```text
+-----------+--------+--------------+
| 姓名      | 城市   | 出生日期     |
+-----------+--------+--------------+
| 赵伟      | 上海   | 2005-09-02   |
| 赵芳      | 广州   | 2005-09-03   |
| 赵娜      | 深圳   | 2005-09-04   |
| 赵秀英    | 杭州   | 2005-09-05   |
| 赵敏      | 成都   | 2005-09-06   |
+-----------+--------+--------------+
```

`AS` 只改**这次结果的表头**，表里的列名一个都没动，下次 `DESC students` 看到的还是 `name`。中文别名直接写就行，不用加引号 —— 上面这张表头就是证据。`AS` 还可以省略（`name 姓名`），但我不建议，省了容易让人读岔。

### 4. `LIMIT`：只看前几行

`LIMIT 10` 意思是「最多给我 10 行」，表里有 200 行它也只交 10 行；行不够时有几行给几行。第 2 节的 `LIMIT 10` 和第 3 节的 `LIMIT 5` 就是它。`LIMIT` 还能写成「跳过前几行、再取几行」的形式，网页翻页靠的就是这个 —— 第 5 篇讲它为什么越翻越慢。

**但 `LIMIT` 有个隐藏前提：不写 `ORDER BY`，MySQL 不欠你一个固定顺序。** 它交出来的是「这次碰巧排在前面的 10 行」，换台机器、加个索引、数据多插几行，顺序可能就变了。同一个问题，今天查和明天查，行序未必一样 —— 想拿它做测试断言、想让用户翻到第二页还能接着第一页，都必须有排序打底。所以正经写法永远是 `ORDER BY` 打底、`LIMIT` 收口 —— 下一节就是它。

### 5. `ORDER BY` 让结果排好队

```sql
SELECT name, birth_date FROM students ORDER BY birth_date DESC LIMIT 5;
```

```text
+--------+------------+
| name   | birth_date |
+--------+------------+
| 陈英   | 2006-03-20 |
| 陈桂   | 2006-03-19 |
| 陈刚   | 2006-03-18 |
| 陈平   | 2006-03-17 |
| 陈霞   | 2006-03-16 |
+--------+------------+
```

`DESC` 是 descending（降序，大的在前），不写默认 `ASC`（ascending，升序，小的在前）。**「最新 5 个」「分数最高 5 个」都是 `DESC`**；要「最早的 5 个」把 `DESC` 删掉即可。

排序可以排多列（配套实验的【7】）：先按城市，同一个城市里再按 `id`：

```sql
SELECT name, city, id FROM students ORDER BY city, id LIMIT 12;
```

```text
+-----------+--------+----+
| name      | city   | id |
+-----------+--------+----+
| 赵伟      | 上海   |  1 |
| 赵丽      | 上海   |  7 |
| 赵娟      | 上海   | 13 |
| 赵桂      | 上海   | 19 |
| 钱敏      | 上海   | 25 |
| 钱勇      | 上海   | 31 |
| 钱平      | 上海   | 37 |
| 孙娜      | 上海   | 43 |
| 孙洋      | 上海   | 49 |
| 孙明超    | 上海   | 55 |
| 李伟      | 上海   | 61 |
| 李丽      | 上海   | 67 |
+-----------+--------+----+
```

12 行全是上海的 —— 因为 `city` 是第一关键字，`id` 只在同城市内部起作用。**多列排序从左到右一级一级来**，第 5 篇会再用到它。

### 6. `DISTINCT`：把重复的挤掉

`students` 有 200 行，但班级只有 4 个。想看「有哪几个班」，就得让重复值消失（配套实验的【8】）：

```sql
SELECT DISTINCT class_name FROM students ORDER BY class_name;
```

```text
+--------------+
| class_name   |
+--------------+
| 软工210班    |
| 软工211班    |
| 软工212班    |
| 软工213班    |
+--------------+
```

200 行进去，4 行出来。**`DISTINCT` 去的是「整行的重复」**：写 `SELECT DISTINCT class_name, city` 会返回「班级+城市」的组合去重，不是各自去重，这点别搞混。

顺带看一眼配套实验的【6】——同样的问题换个问法，连数量一起要，用的是 `GROUP BY`（第 6 篇的主角，这里先看效果）：

```sql
SELECT city, COUNT(*) AS 人数 FROM students GROUP BY city ORDER BY 人数 DESC;
```

```text
+--------+--------+
| city   | 人数   |
+--------+--------+
| 上海   |     34 |
| 广州   |     34 |
| 深圳   |     33 |
| 杭州   |     33 |
| 成都   |     33 |
| 北京   |     33 |
+--------+--------+
```

`COUNT(*)` 数每组几行，`AS 人数` 把表头换成中文，`ORDER BY 人数 DESC` 让人最多的排最前 —— 注意排序用的正是第 3 节那个别名，**别名不光是给表头换字，`ORDER BY`、`GROUP BY` 都认它**。写到这里，骨架里的每一段你都见过面了。

## 三个必须记住的结论

1. **SQL 的语序是焊死的**：`SELECT → FROM → WHERE → ORDER BY → LIMIT`，谁也不能换位，换位就是 `ERROR 1064`
2. **`SELECT *` 是「我全都要」**：刷屏、费流量、还要多绕一圈回表（第 13 篇）。要几列写几列，`AS` 把表头换成人话
3. **想让结果可复现，`ORDER BY` 不能省**：`LIMIT` 不配 `ORDER BY` 拿到的是「碰巧的前几行」；要唯一值用 `DISTINCT`

## 常见错误

### ❌ 把 `ORDER BY` 写到 `LIMIT` 后面

```sql
SELECT name, birth_date FROM students LIMIT 5 ORDER BY birth_date DESC;
```

```text
ERROR 1064 (42000) at line 1: You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near 'ORDER BY birth_date DESC' at line 1
```

**为什么错**：报错把 MySQL 读到哪儿卡住的原话都告诉你了 —— `near 'ORDER BY birth_date DESC'`，也就是它读完 `LIMIT 5` 之后，认为这条语句已经结束了，后面再冒出来 `ORDER BY` 它就不认识了。**SQL 的五段不是「想到哪写到哪」，顺序由语法规定**，和中文「主谓宾」一个道理。

**正确做法**：先排队，再截断：

```sql
SELECT name, birth_date FROM students ORDER BY birth_date DESC LIMIT 5;
```

<details>
<summary>第一题的答案</summary>

```sql
SELECT name, birth_date FROM students ORDER BY birth_date ASC LIMIT 3;
```

```text
+--------+------------+
| name   | birth_date |
+--------+------------+
| 赵伟   | 2005-09-02 |
| 赵芳   | 2005-09-03 |
| 赵娜   | 2005-09-04 |
+--------+------------+
```

`ASC` 可以省略（它就是默认值），写出来是为了和上一节的 `DESC` 对照。
</details>

<details>
<summary>第二题的答案</summary>

```sql
SELECT DISTINCT class_name FROM students ORDER BY class_name;
```

4 个班：软工210班 ~ 软工213班。这张表是 10 个姓 × 20 个名拼出来的 200 行，班级只有 4 个、城市有 6 个 —— 别把两者记混。
</details>

<details>
<summary>第三题的答案</summary>

```sql
SELECT DISTINCT city FROM students ORDER BY city;
```

```text
+--------+
| city   |
+--------+
| 上海   |
| 北京   |
| 广州   |
| 成都   |
| 杭州   |
| 深圳   |
+--------+
```

6 个城市。不用 `WHERE` 是因为**这不是筛选**，你要的是「表里出现过哪些城市」这个整体信息，筛选只会把行越筛越少，而 `DISTINCT` 是把重复行挤掉。
</details>
