# 10 · 数据类型怎么选：一张表的红与绿对照

> **一句话价值**：看完 `bad_design_demo` 这张反面教材，就知道每个字段该用什么类型。

**难度**：⭐⭐　|　**时长**：约 30 分钟　|　**涉及表**：`bad_design_demo`

## 什么时候你会遇到它

你按 `birthday > '2005-01-01'` 查新生，结果发现「张三，出生于 1900 年」也查出来了 —— 因为生日是字符串，比较是从左到右逐字符比的。

## 本篇你会学到

- [ ] 数值类型：`TINYINT` ~ `BIGINT`、`DECIMAL` 为什么不能用 `FLOAT` 存钱
- [ ] 字符串：`VARCHAR(N)` 的 N 到底限制什么、`TEXT` 什么时候用
- [ ] 日期时间：`DATE` / `DATETIME` / `TIMESTAMP` 三者区别
- [ ] `ENUM` 和 `SET` 的取舍
- [ ] `NULL` 和「空字符串」不是一回事
- [ ] **选型速查表**

## 正文大纲

1. **先看一张丑表**：`DESC bad_design_demo;` 逐字段吐槽
2. **金额为什么不能用 FLOAT**（`0.1 + 0.2 != 0.3` 实验）
3. **手机号为什么不能用 BIGINT**（前导 0、+86、`DOUBLE` 精度）
4. **布尔值为什么不用 VARCHAR**（`'false'` 在 MySQL 里等于 0）
5. **日期时间三兄弟**：
   | 类型 | 存什么 | 时区 | 范围 |
   |---|---|---|---|
   | `DATE` | 2005-09-01 | 无 | 1000-01-01 ~ 9999 |
   | `DATETIME` | 2005-09-01 13:00:00 | 无 | 同上 |
   | `TIMESTAMP` | 同 DATETIME | **自动转 UTC** | 1970-01-01 ~ 2038 |
6. **JSON 字段什么时候可以用**（可以，但不能当「不想设计表」的借口）
7. **动手改造**：把 `bad_design_demo` 改写成正确版本
8. **选型速查表**
