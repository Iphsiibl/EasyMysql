# 16 · 慢查询优化实战：把完整流程走一遍

> **一句话价值**：学会一套可复用的「找慢 SQL → 分析 → 优化 → 验证」流程。

**难度**：⭐⭐⭐⭐　|　**时长**：约 40 分钟　|　**涉及表**：`orders`、`order_items`

## 什么时候你会遇到它

接口要 2 秒，监控告警说你了。你打开代码，几十条 SQL，看哪条都眼熟。这时你需要的是**方法论**，不是灵感。

## 正文大纲

1. **第 1 步：抓出慢 SQL**（慢查询日志 / `pt-query-digest`）
2. **第 2 步：`EXPLAIN` 定位问题**
3. **第 3 步：常见问题类型与对应药方**
   | 症状 | 原因 | 药方 |
   |---|---|---|
   | `type=ALL` + 大表 | 缺索引 | 加索引 |
   | `Using filesort` | 排序字段没索引 | 联合索引 |
   | `Using temporary` | GROUP BY/DISTINCT | 改写 / 提前聚合 |
   | 扫描行数 ≫ 返回行数 | 索引区分度差 | 换索引 |
   | `OR` 拖后腿 | 部分列无索引 | 改 `UNION ALL` |
4. **实战一：分页优化**（延迟关联）
5. **实战二：批量写入优化**（`INSERT` 攒批、事务、关自动提交）
6. **实战三：`COUNT(*)` 太慢**（用近似值、汇总表、缓存）
7. **优化前后对照表**（用 `SHOW PROFILES` 的真实数据填满）
8. **别过度优化**：什么时候 18 毫秒根本不用管
